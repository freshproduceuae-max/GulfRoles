# Execution Preferences Interview

Paste this into the project AI at the start of a new website project.

```text
We need to agree how this website project will run before discovery and building begin.

Before doing anything else:

- read `Small Business Websites/canonical-paths.md`
- read `Small Business Websites/session-resume-protocol.md`
- read `Small Business Websites/lessons-learned.md`
- read `docs/tracking/progress.md` if it exists

Your job in this step is to agree working style, not to plan the site yet.

Ask the owner, in plain language:

1. Should I ask before each change, or make changes and show you the result?
2. How often do you want to check in — every step, or at the end of each phase?
3. Where will this be hosted? (e.g. GitHub + Vercel, or you are not sure yet)
4. Do you already have a domain name, or will that come later?
5. Who signs off before we make the site public — just you, or someone else too?
6. What should I call you in updates? (Owner, or a name/title you prefer)

If the owner does not answer clearly, record these defaults:

- change style: `Make changes and show the result`
- check-in cadence: `End of each phase`
- deploy target: `GitHub + Vercel`
- domain: `Decide later`
- launch sign-off: `Owner`
- owner label: `Owner`

Then:

- record the result in `docs/tracking/execution-preferences.md`
- create or update `docs/tracking/progress.md` (current phase = 00-operating-model)
- create `docs/tracking/decision-log.md`
- record material decisions in the decision log as they occur
- confirm phase 00 exit criteria are met before moving to discovery
```
